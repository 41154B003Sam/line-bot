1. 專案概述與目標

隨著即時通訊軟體普及，LINE 已成為台灣使用者最主要的日常通訊工具。傳統的「鸚鵡學舌（Echo Bot）」僅能機械式覆誦文字，缺乏實用商業與個人價值；而一般商業 AI Bot 常面臨昂貴的伺服器託管費用與 API 授權支出。本專案以極簡架構、完全零成本、高穩定度為核心目標，完成第一版（v1.0）LINE 智慧對話機器人的設計與上線。

🎯 關鍵目標 (Key Goals)

  • AI 智慧化賦能：由純 Echo Bot 升級至 Google Gemini AI 模型。
  • 零營運成本：善用 Google AI Studio 免費額度與 Cloudflare 免費隧道。
  • 極致用戶體驗：排版去粗體星號、限制手機閱讀字數、貼圖已讀不回。
  • 企業級安全標準：落實金鑰隔離、簽章驗證與零機密外洩防護。

📊 交付物清單 (Deliverables)

  • Flask + LINE Messaging API v3 後端主程式 (app.py)
  • 繁中版專案規格說明文件 (README.md, walkthrough.md)
  • 機密隔離與依賴清單 (.env.example, requirements.txt)
  • 公開 GitHub 開源儲存庫 (41154B003Sam/line-bot)
  • 完整專案計畫書與成果簡報 PDF

2. 系統架構與資料流向

整體系統採用非同步事件驅動設計，使用者於手機端觸發訊息後，經由 LINE 官方雲端推送至公開 HTTPS 端點，後端伺服器在安全驗證後與 Google Gemini 運算中心通訊並立即回覆。

[LINE 使用者手機]
│
▼ (發送文字 / 貼圖)
[LINE Messaging API 雲端伺服器]
│
▼ (Webhook POST /callback + X-Line-Signature)
[Cloudflare Tunnel 邊緣節點 (HTTPS 穿透)]
│
▼ (轉發本地請求)
[Flask 應用伺服器 (app.py :5000)]
├─► 1. 驗證 HMAC-SHA256 數位簽章
├─► 2. 判斷訊息型態 (Sticker/Emoji ➜ 僅記錄日誌，已讀不回)
├─► 3. 呼叫 Google Gemini API (多模型備援序列)
├─► 4. 輸出文字後處理 (移除 ** 星號、500 字安全句尾截斷)
└─► 5. 透過 LINE Reply API 發送格式化回覆
│
▼
[使用者手機即時收到流暢解答]

3. 核心技術規格與特色機制

3.1 Google Gemini AI 智慧整合與模型序列備援

為避免因單一模型於尖峰時段發生 503 High Demand / Resource Exhausted 錯誤導致服務中斷，後端實作了動態降級備援機制（Fallback Chain）。系統將依序嘗試以下模型群：

優先順序 模型名稱 設計特性 備援觸發機制
Priority 1 gemini-flash-latest 最新版 Flash 模型，反應速度極快，綜合理解力最佳 主模型，預設呼叫
Priority 2 gemini-3.8-flash 次世代預覽架構，具備優異的邏輯推理與結構化輸出 當 P1 出現 503 或異常時自動切換
Priority 3 gemini-3.5-flash 成熟高穩定版本，推論品質可靠 當 P2 亦繁忙時介入接手
Priority 4 gemini-flash-lite-latest 極輕量化節點，極限降低延遲與資源消耗 終極保護層，確保服務永不中斷

3.2 LINE 聊天場景專屬排版優化

Prompt 工程與後處理管線 (Pipeline)：
  • 長度精準控制：System Prompt 強制要求將回覆字數收斂於 250 至 450 字之間（絕對上限 500 字）。
  • 語意完整不截斷：將 max_output_tokens 提升至 2048，避免模型輸出到一半斷頭；若輸出偶然超出 500 字，演算法會在倒數最近的句號（。、！、？、換行）進行安全句尾收斂，絕不殘留半句話。
  • 去除 Markdown 星號：LINE 原生聊天室並不直接支援雙星號粗體語法（**文字** 會直接以星號原始字元呈現，造成閱讀雜亂）。程式後處理自動過濾 **，轉化為清晰自然的純文字排版。
  • 台灣繁體親切語氣：預設繁體中文語境，搭配適量親切表情符號（Emoji）與條列條理化呈現。

3.3 貼圖與 Emoji 「已讀不回」智慧過濾

為解決聊天室中貼圖導致機器人無意義自言自語或浪費 Gemini API 額度的問題，系統實作了特定事件處理器：

  • 針對 StickerMessageContent：完全攔截，記錄 package ID 與 sticker ID 於伺服器日誌，不發送回覆請求。
  • 針對純 Emoji 輸入：過濾僅包含表情符號的文字訊息，實現「已讀不回」的自然對話邏輯。

4. 系統穩定性與資安防護架構

4.1 跨平台編碼保護 (Windows CP950 UTF-8 修復)

在 Windows 繁體中文環境下，終端機標準輸出預設為 cp950 / Big5 編碼。當 Gemini AI 回覆包含特殊 Emoji 或罕見字元時，會引發 UnicodeEncodeError: 'cp950' codec can't encode character 導致伺服器崩潰。本專案於伺服器初始化前置入了底層重定向防護：

if sys.platform == "win32": sys.stdout.reconfigure(encoding="utf-8", errors="replace") sys.stderr.reconfigure(encoding="utf-8", errors="replace")

4.2 金鑰隔離與資安規範實踐

🔒 敏感資訊安全管理

  • 完全拒絕硬編碼：所有 Token 與 API Key 均自 .env 讀取。
  • Git 嚴格排除：.gitignore 明確排除 .env 與 Python 快取，歷史提交經審核無任何金鑰洩漏。
  • 範本標準化：提供 .env.example 供第三方無痛設定。

🛡️ 介面安全與健康度監控

  • HMAC 簽章認證：所有 Webhook 請求強制驗證 X-Line-Signature，無效簽章直接拋出 HTTP 400。
  • 無外洩健康檢查：/health API 僅以布林值 (Boolean) 揭露金鑰配置狀態，不輸出金鑰本體。

7. 後續版本擴充藍圖 (Roadmap v2.0 & v3.0)

🚀 v2.0 預計升級重點

  • 圖文選單 (Rich Menu)：建立客製化九宮格選單，提供「快速指令」、「天氣查詢」、「日常閒聊」等直覺點選功能。
  • 多輪對話記憶 (Session Context)：導入輕量級 SQLite 或 Redis 快取，支援上下文連續問答（例如：「上個問題中提到的...」）。
  • 多模態圖片理解：接收使用者上傳的照片，調用 Gemini Vision 能力進行圖文識別與影像分析。

🌐 v3.0 雲端與自動化擴展

  • 雲端無伺服器託管：將 Flask 容器化部署至 Google Cloud Run 或 Render，擺脫本地電腦持續開機需求。
  • 用戶權限分級：區分公開使用者與管理員身分，管理員可透過指令查詢後台運行指標與 Token 消耗量。
  • 自訂知識庫 (RAG)：連接外部 PDF 或 Google Docs 打造專屬企業或學術領域專家 Bot。
