LINE BOT v1.0 專案發表與架構審查
【主題名稱】智聊小精靈 (Gemini Smart Bot)
基於 Google Gemini 模型之繁體中文生活智慧對話助理
具備端到端非同步通訊、四重模型自動降級備援、500字安全句尾截斷、排版去星號清洗與貼圖已讀不回機制，實現 100% 零維運成本的對話助手。
發表者： 41154B003Sam
技術架構： Python / Flask 3.1 / LINE SDK v3 / Gemini API
儲存庫： github.com/41154B003Sam/line-bot
Target Audience & Purpose 需求與痛點分析
目標客群與欲解決的核心問題
誰會使用這個 LINE Bot？它致力於解決什麼痛點？
👥 目標客群 (Target Audience)
  • LINE 高頻度日常使用者：習慣以 LINE 作為主要通訊介面的學生、上班族與長輩。
  • 需要即時獲取知識與生活靈感者：希望不離開通訊軟體，就能快速查詢旅遊景點、美食建議、文案撰寫或名詞解釋。
  • 偏好極簡且無廣告干擾者：厭倦複雜 App 下載或充斥推播廣告的商業公眾號，追求純粹的一對一 AI 問答。
🎯 欲解決的核心問題 (Problem Solved)
  • 解決跨 App 查詢之摩擦力：免開啟瀏覽器或特製 AI 工具，在日常 LINE 聊天室內即可隨時召喚 AI 助理。
  • 告別死板關鍵字與鸚鵡學舌 (Echo)：突破傳統機器人只能關鍵字匹配或機械式覆誦的限制，賦予真正的自然語意理解能力。
  • 消除長篇大論與格式混亂：傳統 AI 容易輸出過長字串或在手機上顯示突兀的 Markdown 粗體星號，本助理專門針對手機螢幕做閱讀收斂。

Core Functionality 技術深度剖析
本次核心功能：繁中語意問答與排版收斂引擎
深入詳述第一版（v1.0）所實作的旗艦級核心機制
🧠 Gemini 整合
以 Google 官方 google-genai SDK 驅動，設定繁體中文台灣語境與熱心幽默角色提示。
🔄 四重模型降級
gemini-flash-latest ➜ gemini-3.8-flash ➜ gemini-3.5-flash ➜ gemini-flash-lite，無懼 503 限流。
✂️ 句尾安全截斷
嚴格將內容控制在 500 字內，若超長則在倒數最近的標點（。、！、？）完整收尾，絕不留下半句。
🧹 排版星號清洗
全面去除 LINE 不支援的 ** 粗體符號，轉化為親切 Emoji 與換行條列，維持手機版面清爽。
⚙️ 核心處理管線 (Pipeline)：
Webhook 接收文字 ➔ 驗證簽章 ➔ 調度 Gemini 生成 (max_output_tokens=2048) ➔ 移除 ** ➔ 字數邊界檢查與句號截斷 ➔ 回傳 LINE Reply API。

Testing Plan 品質驗證
測試計畫：三大測試情境與預期結果

情境一：正常對話與格式驗證測試
測試操作：
使用者發送日常問題：「請用繁體中文解釋什麼是機器學習？」

預期結果：
• 伺服器成功解析 Webhook 並呼叫 Gemini
• 回覆字數落在 250 ~ 450 字之間
• 無任何 ** 粗體星號，句尾以句號完整結束
• LINE App 順利收到流暢繁中訊息
情境二：貼圖與純 Emoji 過濾測試
測試操作：
使用者於聊天室傳送一張哭臉貼圖或發送純表情符號「😭」。

預期結果：
• 伺服器記錄 StickerMessageContent 或純表情 Log
• 不呼叫 Reply API，已讀不回
• 不浪費 Gemini API 額度
• 聊天室安靜無多餘報錯
情境三：尖峰流量模型自動降級測試
測試操作：
模擬主模型 gemini-flash-latest 遭遇 503 伺服器繁忙限流。

預期結果：
• 系統捕捉異常並於日誌打印 Warning
• 無縫切換至 gemini-3.8-flash 備援模型
• 使用者端完全無感，依然正常收到回覆
• 服務不中斷、不報 500 內部錯誤

LINE Bot v1.0 成果報告 Slide 07 • 成果審查
Unfinished Parts & Issues 誠實檢討與演進
第一版未完成部分與待改善問題
誠實列舉當前版本的局限性，作為下一階段開發重點
1. 缺乏多輪對話記憶
現狀：目前每次對話皆為獨立無狀態 (Stateless)，無法記住上一句脈絡。
改善：導入 SQLite 或 Redis 儲存最近 3~5 輪 Session 歷史。
2. 本地伺服器依賴
現狀：服務依賴本地電腦開機與臨時 Cloudflare 隧道，休眠即中斷。
改善：容器化 Docker 封裝並部署至 Google Cloud Run 或 Render。
3. 缺少圖文選單
現狀：聊天室底部無 Rich Menu，初次使用者不知能問什麼。
改善：設計六宮格圖文選單，提供快速功能快捷鍵。
4. 尚未支援多模態圖片
現狀：用戶傳送照片時被略過，無法分析圖片內容。
改善：新增 ImageMessageContent，串接 Gemini 視覺辨識分析影像。
