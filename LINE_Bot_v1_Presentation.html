Project Motivation & Evolution 階段演進歷程
從鸚鵡學舌 (Echo) 到智慧 AI 助理
為了解決傳統 Bot 缺乏實用功能與雲端高額費用的兩大痛點
❌ 傳統面臨的痛點與限制
  • 回音機器人無實質價值：單純 Echo 複製訊息，無法回答知識與生活問題。
  • AI Token 配額枯竭：呼叫單一模型常遭遇 503 伺服器繁忙，直接中斷回應。
  • 手機排版體驗不良：Markdown ** 星號雜亂、回答過長導致斷句或洗版。
  • 貼圖引發無意義回覆：用戶發貼圖時機器人胡亂回話，耗損 API 額度。
✨ v1.0 提供的全方位解法
  • Google Gemini 官方 SDK 賦能：提供即時推理能力，聰明回答各類問題。
  • 四重模型自動降級 (Fallback Chain)：尖峰時刻無縫切換備援模型。
  • 專屬繁中 Prompt 與安全截斷：嚴控 500 字以內，並於句號處自然收尾。
  • 貼圖/純表情已讀不回：符合真人社交習慣，節省大量運算資源。

AI Engine & Fallback Strategy 高可用性設計
Google Gemini 智慧整合與四重模型備援
消弭免費版在高流量時的 503 服務拒絕風險
第一優先 (Primary)

最新正式版 Flash，速度快、語意理解最佳，負責 90% 以上日常查詢。
第二順位 (Backup 1)
gemini-3.8-flash
最新架構預覽版，當主模型遭遇流量尖峰限流時自動接管。
第三順位 (Backup 2)
gemini-3.5-flash
經典穩定版本，提供高可靠的常規回答，作為第二道保險。
第四順位 (Last Resort)
gemini-flash-lite
超輕量化版本，超低資源消耗，確保終極極端狀態仍能發送回覆。
🛡️ 容錯切換演算法 (Try-Catch Multi-Model Loop)
若當前模型拋出異常（如 503 Service Unavailable），伺服器將記錄警告日誌並無縫進入下一個備用模型，對使用者完全透明無感。

👾 貼圖與 Emoji 「已讀不回」設計
  • StickerMessageContent 專屬處理器：接收貼圖事件後僅於背景記錄 ID，不觸發 LINE Reply 回覆。
  • 純表情符號過濾：若文字僅包含 (emoji) 或 Unicode 圖標，直接返回忽略。
  • 效益：大幅節省每月 API 呼叫配額，同時符合真人社交習慣（已讀貼圖無需回話）。
💻 Windows 繁中 CP950 編碼修復
  • 崩潰根因：Windows 終端機預設使用 Big5 / CP950，列印 Gemini 輸出的多位元組 Emoji 會直接造成致命例外崩潰。
  • 底層注入修復：
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
  • 成果：無論終端列印任何特殊符號，伺服器均維持 100% 穩定常駐。

🚀 v2.0 近期規劃 (互動與體驗升級)
